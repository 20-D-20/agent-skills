## 4. 不触发条件（满足任一即跳过架构文档检查）

| 变更类型 | 说明 |
|---------|------|
| 函数内部实现细节调整 | 算法优化、变量重命名、循环重构，未改变对外接口与调用关系 |
| 修复 Bug 但未改变模块边界 | 仅修正逻辑错误、边界条件、寄存器配置；可考虑写 `dev_notes.md` |
| 注释、日志、格式化、typo 修正 | 不影响行为的纯文本改动 |
| 参数调优 | 修改宏定义、阈值、超时时间等数值常量，未引入新依赖 |
| 单纯的代码搬移 | 文件/函数移动但保持原有调用关系和层级 |
| 已有调用链上的小幅扩展 | 在已记录的功能链上加一个同层函数调用，不跨越新的层级 |

## 5. 渐进式披露判定（决定内容写在主文档还是子文档）

写任何新内容前，对照三维信号判定：

| 维度 | 留主文档（第 0/1 圈） | 拆子文档（第 2 圈） |
|------|---------------------|-------------------|
| **跨模块度** | ≥3 个模块共享 / 引用 | ≤2 个模块关心 |
| **变更频率** | 月级以上稳定 | 周级 / 高频迭代 |
| **细节深度** | 摘要 / 索引 / 一句话 | 展开 / 教程 / 代码片段 |

**判定规则**：三项中**任意一项落右列**，就应该写子文档；只有三项**全部落左列**，才进主文档。

### 判例参考

| 内容 | 判定 | 理由 |
|------|------|------|
| 新建 `wifiTask` 任务条目 | 主文档 | 全局任务，多模块感知，稳定，摘要型 → 三项全左 |
| `page_meas` 的 3 个控件焦点顺序 | `gui_pages.md` | 只 1 个模块关心 + 展开型 → 跨模块度、细节深度都落右 |
| RecStore FIFO 淘汰的具体算法 | 不写文档（看代码） | 模块内部实现，无跨层意义 |
| GUI 任务栈溢出的坑点 | `dev_notes.md` | 一次性历史事件 → 变更频率不适用，但属于诊断类 |
| 新增 `RingBuf_Peek()` 函数 | `tools_index.md` | 通用工具，索引型 |
| 新增"WiFi 手机通信"完整时序 | 主文档 关键业务流程 | 跨 ≥3 模块（USART3→btTask→wifiTask）→ 跨模块度落左、细节落左（摘要）、稳定 → 三项全左 |

### 反例（禁止）

- ❌ 在 `architecture.md` 写"page_meas 按下 UP 键时焦点切换到坐标系图标" → 属于 `gui_pages.md`

- ❌ 同一信息在主文档和子文档各写一份 → 必然漂移，选一处放索引/链接

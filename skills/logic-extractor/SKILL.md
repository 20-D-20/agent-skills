# 业务逻辑提取 (logic-extractor)

## 触发条件

**显式命令**：`/logic-extractor <入口点>`，入口点可以是文件路径、模块名、关键词，或对需求的口头描述。

**关键词自动识别**（无需显式命令也应主动调用）：
- "看不懂这段业务逻辑" / "这块代码到底在干嘛"
- "帮我梳理一下 XX 的决策逻辑 / 业务流程"
- "为什么要这样设计" / "为什么不直接 XX"
- 用户想搞清楚某个跨模块流程的来龙去脉，但记不清细节

## 核心原则

1. **提炼决策骨架，不讲代码实现**——目标是回答"做了什么关键决策、为什么这样做、状态如何流转、边界怎么处理"，不是逐行解释代码。
2. **换叙事视角，不删技术细节**——具体的宏名、指令、驱动状态名该保留就保留（它们是真实可复用的技术细节，删了反而失去价值）。只是不要写成"XX 项目里怎么做"的项目叙事口吻，而要写成"这类器件/协议通用的处理方式是..."的技术视角，这样换个项目遇到同类问题时依然能直接套用。
3. **推不出"为什么"时，直接给出最合理的工程解释**，不做置信度标注，保持文档简洁。

## 执行流程

1. **确定入口点**：用户指定的文件、模块或关键词；若只有口头描述的需求（尚无代码），直接基于需求整理，跳过代码追踪。
2. **跨模块追踪**：从入口点出发，顺着调用链跨文件、跨层追踪相关决策，直到不再产生新的决策点为止（通常止于进入通用 HAL / 工具函数层，这些层级本身不含业务决策）。追踪范围较大、涉及文件较多时，委托 Explore 子代理去读代码，自己只做归纳。
3. **转换叙事视角**：把"项目里怎么做"改写成"这类技术场景通用的处理方式"，具体的宏名/指令/状态名照常保留。
4. **查重**：搜索 `C:\Users\25076\Documents\Obsidian Vault\Doc by AI\技术说明文档\` 下是否已有同主题文档；若有，询问用户是"更新已有文档"还是"新建一份"。
5. **生成并保存**：按下方模板生成文档，文件名格式 `{领域} - {主题}.md`，领域取通用技术类别（如"嵌入式通信"、"STM32"、"蓝牙透传"），不写具体项目名。

## 输出模板

```markdown
# {领域} - {主题}

## 背景与目标 (Context & Goal)

（一句话：这个流程要解决什么问题，什么场景下会触发）

## 状态机 (State Machine)

（关键状态与转换条件，具体状态名/宏名可保留；优先用 Mermaid stateDiagram 或表格，不用大段文字描述）

## 关键决策点 (Key Decisions)

（逐条列出：做了什么决策 + 为什么这样做 + 曾经/可能的备选方案为什么被否决）

| 决策点 | 选择 | 原因 | 被否决的备选方案 |
|--------|------|------|------------------|
|  |  |  |  |

## 执行步骤骨架 (Process Skeleton)

（不出现代码，只描述步骤本身和分支条件，具体指令/接口名可保留；**优先用 ASCII 流程图**呈现顺序与分支，不用编号列表堆文字。每条独立流程画一张图，分支用 `├─`/`└─` 或左右并列表达；示例：

```
发起扫描
   │
   ├─ 当前已连接/透传 ──► 先断开 ──► 等待断开完成 ──┐
   │                                              │
   └─ 当前空闲 ───────────────────────────────────┤
                                                   ▼
                                            发起扫描指令
                                                   │
                                                   ▼
                                            等待扫描完成/超时
```
）

## 边界与异常处理 (Edge Cases)

（重复触发、超时、异常状态等边界情况下的应对策略）
```

## 自检清单

- [ ] 叙述视角是"这类技术场景通用的处理方式"，不是"XX 项目里怎么做"
- [ ] 具体的宏名/指令/状态名该保留的都保留了，没有为了"通用化"而删掉有价值的技术细节
- [ ] 每个决策点都说明了"为什么"，而不只是"做了什么"
- [ ] 状态机/流程优先用图表呈现（状态机用 Mermaid，步骤骨架用 ASCII 流程图），没有用编号列表堆大段文字
- [ ] 文件名格式为 `{领域} - {主题}.md`，领域是通用技术类别而非项目名
- [ ] 若目标目录已有同主题文档，已确认是更新还是新建
